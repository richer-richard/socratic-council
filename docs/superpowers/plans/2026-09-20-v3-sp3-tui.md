# v3 Sub-project 3: TUI on the Engine Event Stream Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The terminal client renders the deliberation the engine actually runs: a Session screen with a rounds timeline, the board, the convergence judgement and the decision record, driven by a pure reducer over the engine's own events; a Home that picks the council preset and the deliverable; Settings that edit the roster, the moderator and utility slots, the tool policy, the protocol and the budget; a sessions list that shows records and cost. The v2 chat vocabulary (adapter, transcript turns, votes, peer evaluation, canvas, tensions) is removed.

**Architecture:** `cli/src/tui/view.rs` holds `SessionView` and `apply(&mut self, DebateEvent)`, the terminal twin of the desktop's `session/reducer.ts`, plus `SessionView::from_stored(&Value)` for session files (v2 fields; a v1 file becomes a legacy transcript). `cli/src/tui/session.rs` renders it. The engine is the only writer of session files (the TUI's own persistence goes). Questions and tool approvals are answered from the screen through `EngineInput`. Settings edit `Config` in place and save it.

**Tech Stack:** Rust, ratatui, crossterm, tokio, serde_json, the `socratic-council-engine` crate.

**Spec:** `docs/superpowers/specs/2026-09-19-one-engine-structured-deliberation-design.md` (sections 9 and 11)

**Status:** complete. Task 1 d516ee3, Task 2 75a7e74, Task 3 b327e73, Task 4 de1f314, Task 5 in the commit that carries this line (ratatui 0.30 and crossterm 0.29 migrated; reqwest 0.13 left to a later pass).

## Global Constraints

- Every string that came from a model or a network passes `sanitize_terminal` before it enters a ratatui buffer (tokens and thinking at apply time; stored content at load time; structured fields at render time).
- Keys never render in plaintext and never reach a log; the key buffer stays masked; proxy URLs render with userinfo redacted.
- Never fabricate model ids: a seat's explicit id must exist in the catalog or the live scan of its provider, else the edit is refused.
- Gates: `cargo fmt --all --check`, `cargo test --locked --workspace`, `cargo test --locked -p socratic-council --no-default-features`, `cargo clippy --workspace --all-targets --locked -- -D warnings` (both feature sets), `cargo audit --deny warnings`; the TS gates are untouched by this sub-project. `cargo clean` at the root after the last task.
- Commits carry no attribution trailers.
