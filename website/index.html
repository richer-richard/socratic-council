How a session moves

Not a chat with eight voices. A protocol with a record at the end.

The moderator frames the question and routes the work. Seats write independent positions in parallel, then cross-examine each other with tools. A utility model rewrites the board after every round and the moderator judges convergence; when the seats stop moving, a revision round collects final positions and votes and the record is written.

01

Framing: the deliverable, the exact question, the options, who leads and who supports, a lens per seat, and a cost estimate before anything runs.

02

Rounds: every seat writes independently and in parallel; cross-examination lets them call web search, claim verification, attachments, workspace files and a sandboxed shell.

03

Closure: the board tracks what is settled and what is disputed, the moderator judges convergence, and the run ends in a decision record with dissent, evidence and next actions.

What leaves the room

The record, the board, the rounds, and a hand-off folder.

The decision record states the answer with its confidence, the votes, the dissent and why it did not carry, what changed, the evidence, the open questions and the next actions. A document deliverable gets a draft, a critique round and a revision instead. Every run ends in a hand-off folder you can point a person or an agent at.

Record
The answer, its confidence, dissent, evidence and next actions, copied as Markdown.
Board
Settled points, disagreements, evidence and open questions, rewritten every round.
Hand-off
A brief with a next-steps checklist, plus the record, the document, the board and the session file. Markdown, PDF, DOCX, PPTX and a portable bundle export locally.
Cost
An estimate before the run, a per-seat ledger during it, session and daily caps, and redacted diagnostics when something goes wrong.

Build from source

The repo is the product perimeter, so the install path is explicit by design.

Quick install exists for macOS. The manual path remains the source-of-truth for people who want exact control over prerequisites, toolchains, and the desktop bundle. The terminal workstation installs on its own with cargo install socratic-council.

Quick install

`install.sh` checks Xcode CLT, Homebrew, Node.js, pnpm, and Rust, then builds and places the app in `/Applications`. 

git clone https://github.com/richer-richard/socratic-council.git
cd socratic-council
./install.sh

Manual install

The README walks through system prerequisites, Node 22+, pnpm 9.15.0, Rust stable, and the Tauri development and production commands for macOS, Windows, and Linux.

  • Node.js 22 or newer
  • pnpm 9.15.0 via corepack
  • Rust stable 1.82 or newer (1.88 for the CLI)
  • Tauri v2 platform prerequisites

For builders

The repo stays compact: one Rust engine, a desktop shell, a terminal CLI, and two shared packages.

The engine crate in `engine/` runs the deliberation for both surfaces. `apps/desktop` hosts it behind a Tauri backend that brokers every outbound byte; `cli/` hosts it in a ratatui TUI. `packages/shared` and `packages/core` hold the event types and the model registry.

Core commands

pnpm --filter @socratic-council/desktop tauri:dev
pnpm --filter @socratic-council/desktop tauri:build
pnpm test && pnpm lint && pnpm typecheck
cargo test --workspace
cargo run -p socratic-council -- run "Is P = NP?"
